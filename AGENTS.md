# Правила разработки EgoFocus

## Текущий объём работ

Подготовлены среда, локальный репозиторий, зависимости и базовые конфигурации. Пользователь разрешил заранее установить вероятные будущие зависимости выбранного стека; это не утверждает функциональные требования. Пользователь поручил разработать базовое приложение по новому ТЗ: русский интерфейс, только тёмная изумрудная тема, Liquid Glass, три вкладки, локальная авторизация, непрерывная история состояний от рождения, статистика и профиль. Клиент находится в frontend/, серверный API в backend/. Из корня Docker Compose запускает PostgreSQL и API. Подключение клиента к API и синхронизация — следующий этап. Проверки в браузере самостоятельно не проводить; давать пользователю ссылку и команды запуска. GitHub пользователь подключает самостоятельно.
Описание функций из исходного документа не является техническим заданием этого проекта. Функциональные требования будут согласованы отдельно.

## Условия

- Разработка на Windows 11, проверка на физическом iPhone. Не предполагать наличие Xcode на Windows.
- Только бесплатные инструменты и бесплатные тарифы без обязательной оплаты после пробного периода.
- Не требовать покупки или аренды Mac и платного Apple Developer Program.
- Личное использование; App Store и TestFlight не требуются.
- Допустима повторная подпись бесплатным Apple ID каждые 7 дней; ограничения проверять по актуальной документации и на устройстве.

## Технические правила

- Основной стек: React Native, Expo стабильной совместимой версии, TypeScript; Node.js LTS и npm; редактор Visual Studio Code, контроль версий Git.
- Expo CLI использовать локально через npx; не устанавливать устаревший глобальный expo-cli.
- Добавлять зависимости только при подтверждённой необходимости. Нативные API и способы хранения выбирать после согласования функций.
- Не менять стек без существенной причины. Не добавлять серверную инфраструктуру без необходимости.
- Перед использованием библиотек, SDK, API и CLI получать актуальную документацию через Context7: resolve-library-id, затем query-docs по конкретному вопросу. Для Apple дополнительно использовать официальную документацию.
- Сохранять совместимость с установленным Expo SDK и обновлять package-lock.json при изменениях зависимостей.
- Использовать expo-dev-client, Metro и Fast Refresh для быстрой проверки изменений, когда будет создан проект.
- Объяснять категории изменений: A — JS/TS и интерфейс, обычно без пересборки; B — нативные зависимости, конфигурация, extensions и entitlements, требуется сборка; C — пользовательские данные, компиляция не нужна.

## Будущая сборка и установка

- Планируемый маршрут: Windows → GitHub Actions на macOS → неподписанный IPA → Sideloadly для Windows. Настраивать после отдельного поручения и подключения GitHub.
- Сборку запускать вручную, учитывать бесплатные лимиты. Не запускать macOS-сборку на каждую правку.
- Сохранять необходимые расширения при упаковке и подписи; не удалять их ради успешной сборки.
- Не передавать Apple ID, пароли, сертификаты и другие секреты в репозиторий или Actions.
- Не использовать чужие аккаунты, сомнительные сертификаты и обходы систем безопасности.
- Проверять ограничения бесплатной подписи для необходимых возможностей до полноценной реализации. Успешная установка IPA сама по себе не доказывает работоспособность функций.
- Сохранять стабильные Bundle ID и проверять сохранность пользовательских данных при обновлении и переподписи. Не пересобирать неизменённый код только ради обновления подписи.

## Порядок работы и общения

- Объяснять действия кратко, пошагово, на русском; давать точные команды PowerShell и указывать, где они выполняются.
- Самостоятельно готовить файлы и исправления в пределах поручения.
- При ошибках сначала изучать логи, затем устранять причину.
- Отделять проверенные результаты от предположений; не обещать неподтверждённую совместимость.
- Разрабатывать по этапам и проверять результат каждого этапа перед следующим.

## Коммиты

- После каждого завершённого изменения, внесённого агентом, самостоятельно выполнять необходимые проверки и создавать Git-коммит без дополнительного запроса пользователя.
- Push выполнять по запросу пользователя; не включать в коммит посторонние изменения, секреты и локальные данные.
